## 问题组 A: CJK 字体嵌入（喂给 DeepSeek + Kimi + Claude）

### A1. 中文字体在 PDF 中显示为方框/空白

**现状**: 使用 Eisvogel (pandoc LaTeX 模板) + xelatex 生成 PDF，中文偶尔正常、偶尔方框。

**具体问法**:
```
我在 WSL2 Ubuntu 环境下用 pandoc + Eisvogel + xelatex 生成中文 PDF。
字体配置如下:
- mainfont: Microsoft YaHei
- CJKmainfont: 未显式设置

问题: 有时中文正常渲染，有时显示为 tofu（方框）。xelatex 日志里
有 "Missing character" 警告但不是每次都出现。

请问:
1. xelatex 的中文字体回退链到底是什么机制？mainfont 设了微软雅黑，
   CJKmainfont 不设的情况下它会 fallback 到哪里？
2. 为什么同一份 .tex 有时正常有时方框？可能的不稳定因素是什么？
3. 你推荐的最佳 CJK PDF 字体配置是什么？（指定具体的字体名和 LaTeX 代码）
```

### A2. WeasyPrint vs Playwright 中文渲染对比

**具体问法**:
```
我在选 HTML→PDF 的渲染引擎。目标: 中文报告，含表格、代码块、Mermaid 图。

选项 A: WeasyPrint (Python, 纯 CSS 排版)
选项 B: Playwright/Puppeteer (Chromium headless 打印)

请对比:
1. 中文字体嵌入: 哪个更可靠？分别需要什么配置？
2. 分页控制 (page-break-inside: avoid): 哪个更精准？
3. CSS 特性支持度: flexbox/grid/CSS 变量/@page 规则
4. 你推荐哪一个？为什么？

如果你有实际踩过的坑，请具体说明。
```

## 问题组 B: 分页与表格（喂给 DeepSeek + Claude）

### B1. 表格跨页截断

**具体问法**:
```
我在 HTML 中有一个 30 行的表格，转 PDF 时经常在页面底部被截断
（半行文字跨在两页上）。

已尝试:
- CSS: page-break-inside: avoid (Chrome/WeasyPrint 部分支持)
- 手动在 15 行处插入分页符

问题:
1. page-break-inside: avoid 对 <tr> 的支持度到底怎样？
   哪些引擎支持、哪些不支持？
2. 有没有不用手动分页的自动化方案？
   比如 JS 计算行高 → 动态判断是否需要分页？
3. 复杂表格（含合并单元格）的跨页处理有什么最佳实践？
```

### B2. 代码块在页边界断裂

**具体问法**:
```
20 行的代码块在 PDF 中经常从中间断开，半段在上一页、半段在下一页。

1. 除了 page-break-inside: avoid，还有什么 CSS 属性可以控制这个？
2. 如果是 Playwright 渲染，有没有 JS 层面的"防止代码块断裂"方案？
3. 你建议对代码块做"如果 < 5 行剩余空间 → 整块移到下一页"的逻辑吗？
   怎么实现？
```

## 问题组 C: Mermaid/SVG 图（喂给 Kimi + Claude）

### C1. Mermaid 在 PDF 中乱码

**具体问法**:
```
Mermaid 代码块在 HTML 中正常（mermaid.js 渲染为 SVG），但转 PDF 时：
- Pandoc 不识别 mermaid 代码块 → 输出为纯文本
- 即使预先渲染为 SVG 图片，嵌入 PDF 后中文变成方框

1. 有没有不需要额外工具链的 Mermaid→PDF 方案？
2. SVG 中的中文在 PDF 里为什么还会乱码？（SVG 本身是矢量格式）
3. 如果放弃 Mermaid，有没有"可以被 pandoc 原生渲染"的图表语法？
   （听说 Typst 可以？）
```

**具体问法**:
```
我现在的 PDF 管道: Markdown → pandoc → xelatex → PDF。
听说 Typst 语法更适合 LLM 生成（错误率更低），而且原生支持 CJK。

请客观对比:
1. Typst vs LaTeX: LLM 生成代码的首次正确率差异
2. CJK 支持: Typst 开箱即用吗？需要什么配置？
3. 排版能力: 表格、代码块、数学公式、页眉页脚 —— Typst 是否够用？

5. 迁移成本: 我的 Eisvogel 模板能平替吗？还是需要重写？

**具体问法**:

我目前有两条并行的 PDF 生成路径:

- 路径 B: HTML → Playwright/WeasyPrint → PDF（适合含图表的报告）

维护两套管道的成本在上升。问题:
1. 如果只保留一条，你推荐哪条？为什么？
2. 有没有方案能让"同一份 HTML 同时满足 Pandoc 和 Playwright"？

   LaTeX 中间格式？

```

## 问题组 E: CSS 变量与打印（喂给 Claude + DeepSeek）

### E1. @media print 中 CSS 变量的坑

**具体问法**:
```

:root { --bg-primary: #fafaf9; --text-primary: #1c1917; }

在 @media print 中:

  :root { --bg-primary: white; --text-primary: black; }
}

问题:
1. WeasyPrint 和 Playwright 对 @media print 中的 CSS 变量支持度一样吗？
2. 有没有浏览器引擎在打印时忽略 CSS 变量的情况？
3. 你建议在 HTML 中内联打印样式，还是用独立的 print.css？
```
