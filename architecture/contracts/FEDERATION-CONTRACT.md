# TRIO 联邦契约 v1.0

> 这不是「统一所有子系统」——这是「定义最小公共协议」。
> 每个子系统在自己的业务域内自治，但在接口层必须对齐。

---

## 一、共享约束（所有子系统必须遵守）

### 1.1 实体 ID
使用 `config/entity-id-schema.md` 定义的统一格式：`{type}:{region}:{identifier}`
所有子系统在引用同一实体时必须使用同一 ID。

### 1.2 文件路由
使用 `config/file-routing.json` 定义的规则。
产出文件不直接放在 D:\ 根目录——通过路由表确定目标路径。

### 1.3 门禁最低子集
每个子系统至少执行：
- **D0**: AI 痕迹清除（无「审计」「修正」「v2」「漏了」）
- **C5c**: 关键声明附带置信度标注
- **C8**: 核心结论附带翻转条件

### 1.4 报告 Manifest
每份报告同级生成 `.manifest.yaml`（格式见 `scripts/manifest.py`）。

### 1.5 Neo4j Schema
使用当前活跃版本（v4）的关系类型。
Schema 变更时更新 `config/entity-id-schema.md` 并在 Decision Ledger 记录。

---

## 二、允许分歧（各子系统可以不同）

- Prompt 体系
- 分析流程（P0/C0 是否需要全量执行）
- 评分卡维度和权重
- 报告模板和格式偏好
- 搜索策略和引擎选择
- 面具分工细节（Investor 不一定需要 Kimi 反例搜索）

## 三、子系统契约

### 3.1 TRIO 3.0 分析引擎

| 项目 | 内容 |
|------|------|
| **输入** | 用户问题 · WebSearch 结果 · Neo4j 图谱查询 · 对标库档案 · 文件系统中的原始材料 |
| **输出** | 富 MD 报告 · `.manifest.yaml` · 候选实体/关系/事实 |
| **失败模式** | API 限流 → 降级为单面具 · Neo4j 不可用 → 标注「图谱数据缺失」· 搜索无结果 → 触发不可回答裁定 |
| **交付** | `deliver.sh` → PDF + HTML |
| **门禁** | 25 条（P0-S3-C0-C9-D5） |

### 3.2 TRIO-Stock

| 项目 | 内容 |
|------|------|
| **输入** | 标的清单 · 财务数据（DuckDB）· Neo4j 产业链查询 · TRIO 3.0 行业分析报告 |
| **输出** | 评分卡 · 产业链图谱 · 个股分析报告 · Decision Ledger 条目 |
| **失败模式** | 财务数据源不可用 → 标注「数据缺失」并跳过 · 评分模型漂移 → 触发 recalibration |
| **交付** | 待接入 `deliver.sh`（当前独立） |
| **门禁** | G9 数字溯源 + D0 AI 痕迹清除（待补全） |

### 3.3 TRIO-Investor

| 项目 | 内容 |
|------|------|
| **输入** | Deal 信息 · 创始人资料 · 对标库人物档案 · TRIO 3.0 尽调报告 |
| **输出** | 尽调备忘录 · 投委会材料 · IRON-LAW 合规检查结果 · Decision Ledger 条目 |
| **失败模式** | 非公开信息缺失 → 触发 Step 0 致命缺口扫描 · IRON-LAW 阻断 → 输出阻断原因 |
| **交付** | 待接入 `deliver.sh`（当前独立） |
| **门禁** | IRON-LAW + delivery-gate.sh + D0 AI 痕迹清除 |
