# TRIO 系统全量审计：三大文件夹职责

> 审计日期: 2026-08-11 | 审计面具: DeepSeek
> 范围: D:\TRIO 3.0（核心 OS）· D:\Agent文件（Agent Branch）· D:\工作（数据库）
> 方法: 三个只读调查 agent 全量盘点 + 对照 llms.txt / file-routing-table.md 职责基准

---

## 一、职责基准（既定设计）

| 目录 | 职责 | 依据 |
|------|------|------|
| `D:\TRIO 3.0` | OS 本体：引擎/命令/角色/协议/状态/门禁脚本/设计系统/文档 | llms.txt、.pathconfig rule 6 |
| `D:\Agent文件` | 学术 + 方法论 + 分支知识（Engineer/Stock/Investor/Chemistry/...） | 入口收敛记忆 |
| `D:\工作` | 项目数据：run 产物/报告/对标库/知识库/训练，按项目落库 | file-routing-table |

**审计结论（总评）**：职责定义清晰，但**执行层大面积违反**——三大目录互相收纳对方职责的内容，形成镜像重复。核心病根不是"放错了几个文件"，而是**同一职责内容存在多处副本**，无单一权威源。

## 七、优先级治理建议（按价值/风险排序）

### P0（本周）——收敛重复，建立单一权威源
1. **引擎备份收敛**：TRIO-3.0-backup ×2 + TRIO基础版 + TRIO-Core → 统一归档到 `D:\TRIO 3.0\archive\`，D盘根 .zip 删除或移入归档
2. **对标库合并**：relationship/signal-library → 并入 `D:\工作\对标库\`（去重后），TRIO 3.0/knowledge 只留路径引用
3. **项目交付物归位**：TRIO-Engineer/projects + 光学滤光片 → `D:\工作\项目\{公司}\`
4. **安全清理**：移除 TRIO-Stock/.env、TRIO-Core/neo4j_creds.json 明文凭据；git rm 8 个 .pyc

### P1（本月）——归放规范化
5. **run 产物单一权威源**：确立"项目内 runs/ 为唯一权威"，归档历史 run 合并，废弃 TRIO 3.0/runs/ 僵尸 + reports/runs/
6. **知识库索引修复**：`知识库/index.md` 修正对标库路径；TRIO 方法论文档从 知识库/对标库 归位
7. **决策日志单一化**：中央日志 或 项目内日志 二选一
8. **猎聘爬虫合并**：三处并一处 → `D:\工作\项目\猎聘全量海搜脚本\`

### P2（本季）——卫生
9. 僵尸目录清理（out/、空 skills/）、Neo4j 残留（.mcp.json 移除 neo4j 注册）、状态双写归一（state.json 并入 state/）
10. 第三方仓库（BettaFish/hyperframes 等）移出 Agent文件 到独立第三方目录

## 八、审计置信度与反证

- 本报告所有路径为文件系统实测，置信度 [4]（agent 只读盘点 + 职责表对照）
- **反证**：可能存在被误判为"重复"的文件——例如 TRIO-3.0-backup 可能是某次重大修复前的必要快照（git log 显示"终局修复"提交）。删除前需逐一确认备份目的。
- **反证**：`knowledge/relationship-library` 可能不是对标库的重复，而是"待图谱化的中间态"——但既然 Neo4j 已按 ADR-010 移除，该中间态失去目标，仍应归并或标注废弃。
