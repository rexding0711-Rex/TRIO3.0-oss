# grilling — 对抗性质询

在分析启动前或关键结论形成后，对当前理解进行逐分支的 relentless 追问。每一轮只问一个问题——等待用户回答后再继续。目的是暴露隐藏假设、消解模糊措辞、建立共享理解。

> 偷师 Matt Pocock 的 grilling skill + TRIO 的认知隔离哲学。Matt 原版是单 agent 拷问用户——TRIO 版改为三面具各自有一个"追问权"：Kimi 追问叙事一致性，DeepSeek 追问证据质量，Claude 追问可行性边界。

## Steps

### Step 1: 装载待审材料

从 triage + wayfinder 的输出中装载：
- 核心问题（triage.core_question）
- 已知已知 + 已知未知（wayfinder ??? 节点）
- 不确定关系（wayfinder 虚线边）
- 层级追溯结果

**完成标准**：已装载 ≥4 个信息点（从 triage 和 wayfinder 的 JSON 输出中提取）。

### Step 2: 三面具轮流追问

按以下顺序，每轮一个问题——等用户回答后再下一轮：

```
Round 1: DeepSeek 先问 → 指向最脆弱的证据链
Round 2: Kimi 追问 → 指向叙事中被忽略的反面
Round 3: Claude 追问 → 指向可行性/约束盲区
Round 4+: 按需继续，直到用户说"可以了"或连续 2 轮无新发现
```

**追问规则**：
- 每轮只问一个问题。问多个 = 让人困惑。
- 能通过搜索代码库/知识库找到的事实 → 自己去查，不要问人。
- **决策**是人的——每个决策性问题抛给人，等回答。
- 问题必须具体——"这个假设在什么条件下被证伪？"不是"你怎么看？"

**完成标准**：用户说"可以了"/"继续"，或连续 2 轮追问无新实质性发现。

### Step 3: 记录决议

追问过程中产生的决策/澄清，立即写入：
- 术语澄清 → 更新 `GLOSSARY.md`（或会话内词汇表）
- 架构决策 → 如果是 hard-to-reverse + surprising + real-trade-off → 写 ADR
- 假设修正 → 更新 wayfinder 的已知已知/已知未知

**完成标准**：每个实质性决议都已落笔（术语→词汇表，决策→ADR或会话笔记，假设→wayfinder更新）。

## 追问维度参考

根据分析类型，侧重不同维度：

| 分析类型 | DeepSeek 追问焦点 | Kimi 追问焦点 | Claude 追问焦点 |
|---------|------------------|-------------|----------------|
| 公司尽调 | 财务数据来源？可验证？ | 叙事中有被忽略的反面吗？ | 结论可操作吗？谁来做？ |
| 竞品对比 | 差异数据可比吗？同口径？ | 差异化是真的还是话术？ | 这对客户意味着什么？ |
| 人物评估 | 正面信息的来源独立性？ | 这个人的决策模式一致吗？ | 这个评估用来做什么决策？ |
| 技术评估 | 性能数据有独立验证吗？ | 这项技术的天花板在哪？ | 集成成本/前置条件？ |
| 决策支持 | 如果不做这个决策，最坏结果？ | 有哪些不被讨论的选项？ | 第一步具体动作是什么？ |

## 失败模式

| 模式 | 预防 |
|------|------|
| 追问变成闲聊——问题太开放 | 每个问题必须具体、可回答、指向一个可证伪的声明 |
| 用户被问烦——追问过快 | 每轮一个问题。等回答。不连珠炮 |
| 该查的不查——把事实问题当决策问题问人 | 先搜知识库/代码库。查不到再问 |
| 决议丢失——讨论完了没记录 | Step 3 强制执行——每轮讨论后立刻落笔 |
