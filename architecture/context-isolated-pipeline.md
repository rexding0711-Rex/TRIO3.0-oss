# TRIO 上下文隔离管道 · 工程规格

## 状态
- 置信度：5/5（已工程化，32 亿 Token 生产验证）
- 版本：v1.0
- 日期：2026-06-28

## 一句话
幻觉在传递到下一层之前被截获——不是因为 Audit 面具更聪明，而是因为它没看到 Suggestor 的全部上下文。

## 架构

```
Suggestor (发散搜集)         Auditor (审计核查)          Doer (综合交付)
      │                           │                         │
      │  ≤500 字结构化摘要        │  ≤500 字 PASS/FAIL      │
      │  + 置信度标注             │  + 风险标注              │
      ├──────────────────────────►├─────────────────────────►│
      │                           │                         │
      幻觉高发区                  独立判断区                最终交付区
```

## 三阶段协议

### 阶段 1：Suggestor → Auditor
- Suggestor 搜集后输出不超过 500 字结构化摘要
- 必须包含：核心发现、信息来源、置信度（1-5）、已知盲区
- **禁止**：输出完整上下文、原始对话、中间推理链

### 阶段 2：Auditor 独立审计
- Auditor 只接收 Suggestor 的 500 字摘要，不接收原始上下文
- 执行：事实核查、逻辑校验、omission 检测
- 输出：PASS/FAIL + 风险标注 + 修正建议（≤500 字）
- **关键**：如果 Auditor 发现 Suggestor 未提及的信息 → 标记为 omission 风险

### 阶段 3：Doer 综合交付
- Doer 接收 Suggestor 摘要 + Auditor 审计结果
- 综合判定后输出最终交付物
- 必须包含：结论、置信度分布、未解决的风险

## 为什么上下文隔离能截获幻觉

1. **去相关化**：Auditor 不知道 Suggestor 的推理链，不会继承 Suggestor 的认知偏误
2. **压缩即过滤**：500 字摘要强制 Suggestor 只保留最核心的发现，噪声和幻觉在压缩过程中被丢弃
3. **独立溯源**：Auditor 需要自己验证 Suggestor 的声明——如果 Suggestor 说"来源 A 称 X"，Auditor 必须独立查证来源 A

## 已知局限

- 如果 Suggestor 摘要遗漏关键信息，Auditor 将被蒙蔽（omission 在层间传播）
- 如果两个面具共享同一个上游信息源（如都来自同一篇 PR 稿），隔离效果退化为单点验证
- 500 字阈值为人工设定，尚未针对不同任务类型优化
