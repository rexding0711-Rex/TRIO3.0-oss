## 关键治理规则（防再次乱放）

### R1 · 报告必须进 reports/
- 业务分析报告（尽调/竞品/融资/生态位）→ `reports/`
- **禁止**堆在 `docs/` 或 `out/`
- 2026-08-10 已把 4 份融资材料留在 docs/ 是特例（用户指定），后续新报告进 reports/

### R2 · 项目数据必须进 D:\工作\项目\
- 具体公司/项目尽调数据 → `D:\工作\项目\{项目名}\`
- **禁止**堆在 `runs/`（runs/ 只放 run 状态，不放业务数据）

### R3 · out/ 是临时区，用后即清
- 跑批中间产物（如 batch-extraction-*.json）→ 用完立即清理或归档
- **禁止**长期堆积（2026-08-10 清掉 19 个残留）

### R4 · 架构/方法论各归其位
- 架构设计 → `architecture/`
- 方法论/评估框架 → `knowledge/`
- 不要混在 docs/

### R5 · 过期产物立即归档
- 被新版本取代的旧文件（如 K3 版 BP）→ 立即移 `D:\工作\归档\`
- 不留「版本对比」在活跃目录
