# pre-delivery — 交付前质量门禁

在分析报告交付给用户之前，跑一套完整的质量检查。**这不是可选的——是阻断性的。** 任一 🛑 → 阻断交付 → 补全 → 重跑 → 最多 3 轮。

> 从 CLAUDE.md L0 防线规则提取。独立为技能后，CLAUDE.md 只需 1 行指针。

## Steps

### Step 0: AI 痕迹清除（最先执行，阻断性最高）

交付物中**绝对禁止**以下 5 类 AI 过程痕迹。全文搜索 → 任一命中 → 🛑 阻断。**没有例外。**

| 类别 | 搜索关键词 | 0 命中 = 通过 |
|------|-----------|--------------|
| A1 版本标记 | `v[0-9]` `重做版` `修订版` `审计后` `修正版` `重写` | grep -c = 0 |
| A2 过程注释 | `（审计后` `与上一版一致` `新增章节` `修改过` | grep -c = 0 |
| A3 自指陈述 | `审计发现` `漏了` `感谢.*审计` `这次` `本轮修正` `补充了` `改成了` | grep -c = 0 |
| A4 元数据泄漏 | `topology-state` `对比表` `修正前后` `版本.*对比` `state.json` | grep -c = 0 |
| A5 致谢/道歉 | `TBD` `TODO` `未完待续` `仅供参考` `能力有限` `如有疏漏` | grep -c = 0 |

**完成标准**：5 类搜索全部 0 命中。任一非 0 → 🛑 → 逐条清除 → 重搜。

### Step 1: 排版硬检查（阻断性，10 项）

10 项全部 ✅ → 通过。任一 ❌ → 🛑 阻断 → 修 → 重查。**与 Step 0 并列——AI 痕迹和排版是两件事，不可合并为一步。**

- [ ] B1 表格列数一致？`|` 分隔符连续无断裂？无跨行残缺？
- [ ] B2 Unicode dingbats（✓✗★●）已替换为 ASCII（是/否/Y/N/*）？
- [ ] B3 Mermaid 代码块前有提示？
- [ ] B4 中英文/数字间有空格？
- [ ] B5 标题层级无跳级？标题/代码块/表格前后有空行？
- [ ] B6 链接可点击？裸 URL 已包装为 `[文字](URL)` 格式？
- [ ] B7 无连续 3 行以上空行？列表缩进一致？
- [ ] B8 目录与正文章节数一致？目录不缺失章节、不包含已删除章节？
- [ ] B9 子节编号无冲突？扫描 `### N.M` 无重复编号对（禁止两个 `### 10.1`）
- [ ] B10 章节编号连续？§1→§2→...→§N，无跳号、无重复

**完成标准**：10/10 ✅。

### Step 2: 冗余词汇扫描

全文扫描以下词汇并删除：

```
以下为 | 如下 | 值得注意的是 | 需要指出的是 | 显而易见 | 毋庸置疑 | 
众所周知 | 不难发现 | 可以看出 | XX 展开 | XX 详见 | 我们来看看
```

同时删除括号注释（`（topology-state.json 自动生成）`等）。

**完成标准**：全文搜索上述词汇返回 0 结果。

### Step 3: 拓扑检查

如果交付物涉及结构性分析（行业全量/公司尽调/竞品对比/供应链分析）：

1. 确认 `runs/{run_id}/topology-state.json` 存在且 `ph.0` 到 `ph.4` 全部填写
2. 运行 `bash scripts/topology-check.sh <报告.md> <领域>`
3. 检查退出码：0 = 通过/警告，1 = 阻断
4. C7 逐字段校验：pn/l1/l2/inj/up/dn/rv/tw/mb/mc/ni/atk
5. 聚合节点检查：每个聚合节点（如"供应商""竞品"）是否展开了 ≥3 个具体名称？
6. Mermaid 语法检查：不含 `%` `+` `//` `<br/>` `???`

**完成标准**：退出码 0。所有 C7 字段完整。所有聚合节点已展开。

### Step 4: CJK 字体扫描

如果交付物含中文（PPTX/Word/PDF）：

1. 运行 `python3 /mnt/d/TRIO 3.0/scripts/check-cjk-fonts.py /mnt/d/TRIO 3.0/reports/<文件名>.pptx` （或 .pdf）
2. 检查输出：0 个违规 → 通过。>0 个 → 🛑 阻断

**完成标准**：check-cjk-fonts.py 退出码 0。

### Step 5: 反证覆盖率

统计报告中所有标注了置信度的关键声明，计算附可证伪条件的比例：

```
反证覆盖率 = 附可证伪条件的声明数 / 总声明数
```

阈值：≥ 80%。低于阈值 → 🛑 阻断 → 回补可证伪条件。

**完成标准**：覆盖率 ≥ 80%，结果写入报告末尾：`反证覆盖率: {M}/{N} ({X}%)`

### Step 6: 声明等级标注

确认报告开头包含：
- **声明等级**: [ ] 假说 [ ] 工程规则 [ ] 理论 [ ] 数学定理
- **审计状态**: [ ] 未审查 [ ] 内部审计通过 (L1/L2/L3) [ ] 外部审查通过
- **审计严格度**: L1/L2/L3

**完成标准**：三个标注全部非空。

### Step 7: 交付格式

分析型交付 → 必须产出三件套：

```bash
bash scripts/deliver.sh <报告.md> --theme <A/B/C>
```

**完成标准**：MD + PDF + HTML 三件套全部生成。

## 阻断汇总

| 检查项 | 阻断条件 | 动作 |
|--------|---------|------|
| AI 痕迹 | A1-A5 任一关键词命中 | 🛑 逐条清除 → 重搜 5 类全部 0 命中 |
| 排版 | B1-B10 任一 ❌ | 🛑 修 → 重查 10/10 ✅ |
| 冗余词汇 | 扫描命中 ≥1 个 | 🛑 删除后重扫 |
| 拓扑 | C7 任一字段缺失 / 聚合节点未展开 / 退出码 1 | 🛑 回补 |
| CJK | 检测到拉丁字体用于中文 | 🛑 替换字体后重跑 |
| 反证覆盖率 | < 80% | 🛑 回补可证伪条件 |
| 声明等级 | 任一标注未填 | 🛑 补填 |
| 交付格式 | 三件套不全 | 🛑 跑 deliver.sh |

**3 轮未过** → 报告封面强制标注「⚠️ 未通过交付门禁」，用户确认后放行。

## 失败模式

| 模式 | 预防 |
|------|------|
| 跳过门禁——"这次比较急" | 此技能设为阻断性。不跑 = 不说"完成" |
| AI 痕迹假通过——只删了明显的、漏了隐蔽的 | Step 0 五类搜索全覆盖。A3（自指陈述）最容易被漏 |
| 排版假通过——只看表格没看章节编号 | B8/B9/B10 专门堵章节编号漏洞 |
| 反证覆盖率假通过——可证伪条件写得太模糊 | "在什么条件下被证伪"必须具体到可观测事件 |
| 拓扑检查只跑 C1-C3 漏 C4-C7 | Step 3 逐字段对照——不跳 |
