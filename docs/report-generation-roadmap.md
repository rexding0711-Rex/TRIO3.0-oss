## 后续报告 Roadmap

### Phase 1：基础设施完善（本周）

| 任务 | 优先级 | 说明 |
|------|:---:|------|
| TokenUsage 接入审计框架 | P1 | 审计报告中的成本数据自动从 TokenUsage 取值，不再手动计算 |
| 报告模板化 | P1 | 将 SOP 中的结构模板做成 `report-template.md`，新建报告时复制填充 |
| 数据溯源自动化 | P2 | 搜索结果自动记录来源 URL + 日期到 `data-sources.jsonl` |

### Phase 2：质量闭环（下周）

| 任务 | 优先级 | 说明 |
|------|:---:|------|
| VPS 输出质量盲评 | P0 | 最大证据缺口。需要 ≥3 人独立评分 |
| 行为纪律执行指标追踪 | P1 | 并行率、验证率、任务外化率的实际数据 |
| 审计框架 v1.1 | P2 | 根据审计修正更新维度权重 |

### Phase 3：自动化（两周后）

| 任务 | 优先级 | 说明 |
|------|:---:|------|
| 报告生成脚本 | P2 | `generate-report.sh <主题> <竞品>` 一键触发 5 阶段流程 |
| 数据缓存层 | P3 | 常用数据点 (定价、benchmark) 缓存到 Neo4j，避免每次重搜 |
| PDF 质量检查脚本 | P3 | 自动检查：表格完整性、脚注对应、置信度覆盖率 |

## 下次出报告的触发词

用户说出以下任意组合时，触发 SOP：

- "对比" + 模型/公司/产品名称
- "出报告" / "做一份分析" / "全量对比"
- 明确要求 PDF/Markdown 交付

**触发后必做**：
1. Claude 确认主题和范围
2. DeepSeek 执行维度 0（时间戳确认）
3. Kimi 确定搜索维度和叙事方向
4. 走完整 5 阶段流程
5. 交付前 DeepSeek 终审

## 路线图本身的生命周期

- 每完成一份报告后，更新"已交付报告"清单
- 每次审计发现后，更新 SOP 和审计框架
- 每月回顾一次 Phase 进度
