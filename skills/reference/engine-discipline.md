# 引擎纪律

> 从 CLAUDE.md 提取。TRIO 分析引擎的操作纪律——启动前、运行中、输出后的硬约束。

## 信息流拓扑（不可违反）

引擎执行完毕 → 输出写入 `raw-output.json`（不可直接引用）→ 运行 `./scripts/validate-engine-output.sh raw-output.json --strict` → 只有 `validated-output.json` 的内容可被后续引用。如果 validated-output.json 的 `_validation.status = "BLOCKED"` → 停止 → 不输出结论。无例外·无降级·无跳过。

## 引擎运行规则

- 引擎输出必须附计算过程——L3威胁分/L5综合分必须展示公式+数字。缺过程→引擎run无效
- 引擎输出必须附信号覆盖率——N/6类信号已覆盖。未覆盖类别→标注"可能影响评分准确性"
- 关键数据缺失(样品未到/配方未测)→L5刹车→不评分→输出实验方案
- 引擎是领域无关的——禁止混入"用例不匹配"类自伤判断

## 信号密度预检（阻断规则）

引擎启动前强制执行：
- 目标Case公开数据<3篇可确认来源或<2类信号→拒绝启动引擎
- 标注"⚠️ 信号密度不足·引擎不可用·建议手动调研"
- 已终止/利基无数据Case直接走手动分析
- 禁止在数据不足的Case上强行跑引擎给假精确分数

## 引擎拒绝对话模板

当信号不足被拦截时→输出："公开信息密度不足以支撑有效分析。建议：补充[具体缺失项]后重新启动，或降级为速判模式。"
这类aborted run不计入均分（标记为aborted_insufficient_signal）。
引擎的最高美德不是给出答案——是知道什么时候不给答案。
