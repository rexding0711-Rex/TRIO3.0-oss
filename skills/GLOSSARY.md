# TRIO 3.0 领域词汇表

TRIO 技能系统的统一词汇。每个术语有精确定义、反义词（避免使用）、以及所属上下文。

**粗体**术语本身在本词汇表中定义。

---

## 架构

### TRIO
三个 AI 面具（**Kimi**/**Claude**/**DeepSeek**）并行协同的分析操作系统。核心理念：**认知隔离**——三个视角独立看同一份材料、互不可见、暴露矛盾后再综合。

_避免_: 三件套、三剑客、多 agent 系统

### 面具
TRIO 中的一个独立认知视角，有稳定的人格定义和行为纪律。不是"角色扮演"——是带有验证闭环的认知分工。

_避免_: 角色、人格、agent

### Kimi
洞察面具——负责内容发现、叙事构建、反直觉判断。核心产出：核心判断 + 反直觉发现 + 盲区自白。

_避免_: 内容面具、创意 agent

### Claude
工程面具——负责可行路径、约束识别、交付执行。核心产出：可行方案 + 约束条件 + 盲区自白。

_避免_: 交付面具、务实 agent

### DeepSeek
审计面具——负责质控验证、风险识别、矛盾检测。核心产出：风险点 + 信息缺口 + 少数派保护。

_避免_: 批判面具、验证 agent

### 认知隔离
三个面具并行启动、接收同一份材料、互不可见对方输出。目的是暴露独立判断之间的**自然矛盾**——而非让三个面具互相说服。

_避免_: 多视角、多角度、并行分析

## 分析流程

### CORE.md
TRIO 操作系统内核。包含三根柱子（认知隔离/结构化怀疑/自验证闭环）+ 通用执行规则 + run 初始化检查清单。

### 三根柱子
1. **认知隔离** — 三面具并行、互不可见
2. **结构化怀疑** — 每条关键声明必须附可证伪条件
3. **自验证闭环** — 改代码→写测试→跑→对比→汇报

### Gate 0（致命缺口扫描）
分析启动前的第一道闸：系统列出"哪些信息一旦缺失或错误——会导致后续所有分析作废？"用户决定继续/刹车/补缺口。

_避免_: 前置检查、缺口分析

### Step 2.5（致命弱点中断）
搜索后动态证伪——搜索到的公开信号与用户精确断言直接矛盾时，触发承重判定。承重→刹车；非承重→继续并标注反证。

_避免_: Fatal Flaw Halt、证伪中断

### ESCALATE
四个升级条件——任一满足则触发更深层分析或用户介入：
1. 矛盾无法消解
2. 关键数据缺失且不可替代
3. 结论置信度低于 [3] 但影响重大决策
4. 三面具中有一个持续与其他两个分歧

### 反证覆盖率
报告中附"可证伪条件"的关键声明数 / 关键声明总数。阈值 ≥ 80%。低于阈值 → 阻断交付 → 回补。

_避免_: 可证伪比例、验证覆盖

### 少数派保护
当一个面具持续与另外两个分歧时——不消灭这个少数意见，而是封存、标注、等待更多数据。对抗群体思维的核心机制。

_避免_: 异议保留、少数意见

## 技能系统

### 技能
一个从随机系统中提取**可预测性**的行为单元。不是保证同样输出——是保证同样的**过程**。

_避免_: 命令、能力、工具

### User-Invoked
只有人手动输入技能名才能触发的技能。零 context load，支付 cognitive load（人必须记住它存在）。

_避免_: 手动触发、slash command

### Model-Invoked
Agent 可自动触发的技能——保留 description 字段供 agent 发现。支付 context load（description 每轮都在 context window 里）。

_避免_: 自动触发、后台技能

### 路由技能
一个 user-invoked 技能的职责是列出其他 user-invoked 技能及其触发条件。当 user-invoked 技能多到记不住时，路由技能降低 cognitive load。

_避免_: 调度器、菜单、注册表

### 完成标准
告诉 agent "这一步做完了"的可检查条件。两个属性：清晰（agent 能判断 done vs not-done）和穷尽（不是"产出一份变更清单"——是"每个修改过的模块都已确认"）。

_避免_: 退出条件、完成信号

### 主导词
利用模型预训练中已有的紧凑概念（如 *fog of war*, *tracer bullets*, *tight loop*）来锚定行为——一个词驱动一整片行为区域。在 body 里锚定执行，在 description 里锚定调用。

_避免_: 关键词、触发词、标签

### 信息层级
技能内容的排列——按 agent 需要它的紧迫度排。三档：Steps（inline，最高）→ Reference（同文件，次级）→ Disclosed Reference（linked file，按需加载）。

_避免_: 结构、组织、布局

### 渐进披露
把 reference 推到 linked file 后面——不是省钱，是保护信息层级。只 inline 每条路径都需要的；只某些 branch 需要的 → 推到 pointer 后面。

_避免_: 懒加载、分块

### 上下文指针
命名外部材料 + 编码触发条件的引用。它的**措辞**（不是目标）决定了 agent 什么时候去读、有多可靠。弱措辞 = 方差 bug。

_避免_: 链接、引用、导入

## 失败模式

### 过早完成
当前步骤没真做完就跳到下一步——因为 agent 的注意力滑向"完成"而非"工作"。防御顺序：先磨利完成标准（便宜、局部），只有完成标准不可约地模糊 AND 实际观察到 rush → 再隐藏后续步骤。

_避免_: 仓促完成、跳步

### 沉积
旧内容层层堆积从不清理——因为添加感觉安全、删除感觉危险。没有修剪纪律的技能/规则的默认命运。

_避免_: 堆积、膨胀、腐化

### 臃肿
纯长度过长——即使每行都是活的、唯一的。不同于沉积（因为陈旧）和重复（因为重复含义）。解药：信息层级——推 reference 到 pointer 后面，按 branch 或 sequence 拆分。

_避免_: 膨胀、过长、冗余

### 重复
同一含义出现在多个地方。代价：维护（改一处须改多處）+ token + 膨胀权重——重复让一个含义在信息层级上的位置高于其真实排名。

_避免_: 冗余、重复定义

### 空操作
一句话不改变 agent 的默认行为——你花钱告诉 agent 它本来就会做的事。测试：删掉这句话，agent 行为会变吗？不会 → 空操作。

_避免_: 废话指令、重申默认

### 否定
用禁止来转向——"不要 X"——却把 X 拖进 context 并让它**更**可及。"不要想大象"——大象是唯一在场的东西。解药：提示**正向**——描述目标行为，让被禁的那个从未被说出。

_避免_: 禁止式提示、反向指令

## 交付与质量

### 拓扑门禁
分析型交付前的结构化验证——检查拓扑图节点完整性（pn/l1/l2/inj/up/dn/rv/tw/mb/mc/ni/atk）、聚合节点可展开性、反证覆盖率。C1-C7 逐字段校验。

### M4 训练
基于对标库（82 公司/38 人物）的认知训练体系。每次涉及对标库的分析结束后，强制落库检查（训练日志 + portrait.md 更新）。

### 层级追溯
分析组件/子系统时，强制向上一级追溯——组件→整机→系统→市场准入。防止"局部正确、整体盲区"。

### 三件套
分析型交付的标准输出格式：MD + PDF + HTML。通过 `deliver.sh` 一键生成。
