# @layer: knowledge
# TRIO 六层接口契约

> 每层只对上暴露最小必要接口。接口一旦发布，视为对系统其他部分的承诺。
> 灵感：《模块化解耦与层次化设计》第5章

## 1. 交互层 → 场景层

**交互层职责**: 接收用户指令，路由到对应场景

| 操作 | 输入 | 输出 | 承诺 |
|------|------|------|------|
| `/逆向工程 {target}` | 目标名称 | 启动 deconstruct 场景 | 30s内开始Step0 |
| `/尽调 {target}` | 目标名称 | 启动 due_diligence 场景 | 同上 |
| `/日进化` | 无 | 执行4层日循环 | 20min内完成全部Layer |
| `/速判 {target}` | 目标名称 | 启动 quick_assessment | 10min内出结果 |

**契约**: 交互层不关心场景如何执行——只负责路由。

## 2. 场景层 → 能力层

**场景层职责**: 按SOP编排三面具协作

| 操作 | 输入 | 输出 | 承诺 |
|------|------|------|------|
| 加载场景JSON | 场景名 | 步骤DAG + 角色分配 | JSON schema合规 |
| 执行Step N | 上一步输出 | 当前步输出 + state更新 | depends_on满足才执行 |
| 提取技能 | 完成run的step5 | SKILL.md | 审计通过后才提取 |

**契约**: 场景层不关心具体角色怎么实现能力——只负责"谁在什么时候做什么"。

## 3. 能力层 → 知识层

**能力层职责**: 三面具调用知识库

| 操作 | 输入 | 输出 | 承诺 |
|------|------|------|------|
| 搜索公司 | 公司名 | company-benchmark匹配结果 | 全量扫描 |
| 对标行业 | 赛道名 | 行业基准数据 | 标注置信度 |
| 引用方法论 | 方法名 | knowledge-benchmark匹配 | 标注来源 |

**契约**: 能力层不关心知识库内部结构——只关心"能查到什么"。

## 4. 知识层 → 进化层

**知识层职责**: 知识沉淀

| 操作 | 输入 | 输出 | 承诺 |
|------|------|------|------|
| 执行run | 场景+目标 | step文件 + state.json | 状态转移合规 |
| 入库ADR | 决策记录 | docs/adr/ADR-NNN.md | 格式合规 |
| 记录模式 | 复盘报告 | lessons-learned/ | 跨项目通用 |

**契约**: 知识层不关心进化层怎么用这些数据——只负责"存得正确"。

## 5. 进化层 → 基础设施层

**进化层职责**: 日循环 + 度量

| 操作 | 输入 | 输出 | 承诺 |
|------|------|------|------|
| 日进化Layer1 | 无 | kb-refresh-status.json | 每次reset后更新 |
| 日进化Layer3 | projects.json | 项目状态+里程碑提醒 | 各项独立，单项失败不阻塞其余 |
| sync | 文件系统 | metrics.md + DAILY.md更新 | Python按列名匹配，不改表格格式 |
| guard | 无 | 违规清单 | 30s超时保护 |
| depth | behavior-log | 输出深度level | 防抖动保护 |

**契约**: 进化层不关心基础设施层的实现——只关心"这些操作能不能跑通"。

## 6. 基础设施层

**基础设施层职责**: 文件系统 + 脚本引擎。不向上暴露承诺——只提供操作。依赖方向的最底端。

| 组件 | 功能 |
|------|------|
| mgmt.sh | 总路由，加载8个子模块 |
| scripts/sync.sh | 数据同步 |
| scripts/guard.sh | 禁区扫描+层依赖校验 |
| scripts/depth.sh | 认知负载检测 |
| scripts/behavior.sh | 行为追踪 |
| scripts/daily-fill.sh | DAILY自问填充 |
| scripts/backup.sh | 快照备份 |
| scripts/skills.sh | 技能提取+状态校验 |
| scripts/kb-refresh.sh | 知识刷新调度 |
| config/projects.json | 项目状态唯一真相源 |

## 接口演化规则

1. 新增操作→不影响已有操作→版本号小递增(1.0→1.1)
2. 修改已有操作的输入/输出→标记deprecated 1个版本→移除
3. 破坏性变更→提前同期通知→ADR记录

---

## 域分层（DDD 子域分类）

| 域 | 模块 | 理由 | 改动门槛 |
|------|------|------|:--:|
| 🔴 **核心域** | 三权分立质控、本体论(六层+七层)、日进化引擎、思维记录器 | TRIO 独一无二，不可外包 | 必须先过 /deepseek 审计 |
| 🟡 **支撑域** | 场景 SOP、技能记忆、能力镜像、优雅降级 | 业务需要但不构成壁垒 | 影响评估后改动 |
| 🟢 **通用域** | 备份、同步、格式转换、guard | 现成工具可替代 | 自由改动 |
