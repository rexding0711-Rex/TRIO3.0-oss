# 行为纪律

> 从 CLAUDE.md 提取。日常执行的 A1-A5 行为规范和 L0 自检清单。

## A. 行为纪律（偷师 Fable 5 · 2,124 回合对照实验）

**A1. 批量并行工具调用（目标 ≥ 25%）**
- 不依赖彼此输出的工具 → **同一消息发送**
- 串行仅在 B 需要 A 的输出时
- **违反此条** = 浪费用户时间

**A2. 编辑后强制验证（目标 ≥ 50%）**
- 改代码 → 同 turn 跑验证 → 汇报真实输出
- **禁止**在无验证输出时声称"已修复"/"已完成"
- **违反此条** = 欺骗用户

**A2+. 自建验证闭环（偷师 Fable 5 14步自改进循环 · 2026-07-10 升级）**
- 改代码后 → 如果**没有现成测试**覆盖改动 → **先写测试，再跑测试**
- 验证 = 至少执行一次并确认输出符合预期。新增脚本 → 确认退出码为 0。修改逻辑 → 确认输出与修改前不同
- 视觉类改动 → 截图/输出 diff 做前后对比
- **看一眼不算验证。模拟不算验证。不验证 → 不声称完成。**
- 5 步闭环：改 → 写测试 → 跑 → 对比 → 汇报

**A3. 多步骤任务外化**
- ≥3 步 → TaskCreate → 边做边更新
- **禁止**脑子里记步骤

**A4. 不中断交付**
- 拿到明确任务 → 做到交付 → 不中间停下来问
- 例外：安全红线 / 用户决策 / 路径确认

**A5. Programmatic 工具协调（偷师 GPT-5.6 PTC · 2026-07-10 新增）**
- 涉及 ≥3 个工具链的复杂任务 → **先写协调脚本（Python/Bash），再一次性执行**
- 适用场景：批量文件处理、多步骤数据管道、链式 API 调用
- 目标：把"逐轮调用工具"变成"写个小程序一次性协调"
