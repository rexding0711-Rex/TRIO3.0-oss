# wayfinder — 知识空间定向

在深入分析之前，先画一张"我们知道什么、不知道什么"的地图。防止分析完成后才发现漏了整层。

> TRIO 反复出现的教训：分析完了才发现没覆盖整机认证要求（2026-07-09 车载网关）、没追溯到市场准入层（多次拓扑修复）。wayfinder 在分析启动时就把这些盲区标出来——让"不知道"在分析开始前就可见。

## Steps

### Step 1: 搜索已有资产

在启动新搜索之前，先查 TRIO 已有什么：

1. **知识图谱**：Neo4j 中是否已有该目标的相关节点/关系？（运行 `MATCH (n) WHERE n.name CONTAINS '<target>' RETURN n LIMIT 20`）
2. **对标库**：`D:\工作\对标库\company-benchmark\` 和 `person-benchmark\` 中是否已有相关分析？
3. **历史报告**：`D:\工作\TRIO\Reports\` 中是否已有同目标的历史输出？
4. **Run 记录**：`runs/` 中是否已有同主题的 run-state.json？

**完成标准**：四个数据源全部检查完毕。每次检查输出 yes/no + 具体路径或行数。

### Step 2: 知识空间三区映射

基于 triage 判定的 `type` 和 `depth`，对分析对象做三区映射：

```
已知已知（Known Knowns）
├── <事实1> [来源: <路径或URL>] [置信度: 1-5]
├── <事实2> [来源] [置信度]
└── ...

已知未知（Known Unknowns = ??? 节点）
├── ??? <需要但缺失的关键数据1> — 如果答案是X，结论翻转为Y
├── ??? <需要但缺失的关键数据2>
└── ...

不确定（Uncertain = 虚线边）
├── <关系1> -- <关系2>：可能有但不确定的关联
└── ...
```

**硬约束**：
- `???` 节点必须 ≥ 3 个（如果确实找不到这么多，标注原因）
- 虚线边必须 ≥ 1 条
- 每个 `???` 节点附一条"如果答案是 X，对结论方向的影响是什么"

**完成标准**：三区全部非空。`???` 计数 ≥ 3（或标注了为什么不够）。

### Step 3: 层级追溯

从 triage 的 `layer_trace.asked_layer` 出发，向上一级追溯：

```
被问到: 车载以太网 PHY 芯片（组件层）
  ↓ 向上一问
上一级: 车载网关 ECU（整机层）
  ├── 环境可靠性: ISO 16750（振动/温度/湿度）→ 是否覆盖？ [covered/blind]
  ├── 车载 EMC: CISPR 25 → 是否覆盖？ [covered/blind]
  ├── 功能安全: ISO 26262 → 是否覆盖？ [covered/blind]
  └── 市场准入: CCC / E-MARK → 是否覆盖？ [covered/blind]
```

**规则**：只追溯一级——不需要无穷递归。但如果整机层任何一项标记为 `blind`，报告中必须出现 ⚠️ 标注。

**完成标准**：上层约束清单已列出，每个约束标注了 `covered` 或 `blind`。

### Step 4: 信号源预判

根据分析类型，预判需要哪些数据源——以及哪些可能拿不到：

| 分析类型 | 理想数据源 | 可能缺失的 |
|---------|----------|----------|
| 公司尽调 | 财报 + 新闻 + 研报 + 海关数据 + 专利 + 招聘 | 非上市公司的财务、私企供应链 |
| 竞品对比 | 产品规格 + 定价 + 客户名单 + 融资记录 | 定价（非公开）、客户名单（保密） |
| 人物评估 | LinkedIn + 公开履历 + 演讲 + 专利 + 论文 | 薪酬、内部绩效、非公开决策 |
| 行业研究 | 行业报告 + 政策文件 + 头部公司财报 + 协会数据 | 细分市场数据、实时产能 |

**完成标准**：列出了 ≥3 个目标数据源，标注了 ≥1 个"可能拿不到的"。

## Output Format

将结果写入分析会话的 wayfinder 段（追加到 state.json 或直接输出为 Markdown）：

```markdown
## 知识空间定向: <目标>

### 已有资产
- Neo4j: yes/no ([N] 个相关节点)
- 对标库: yes/no
- 历史报告: yes/no
- Run 记录: yes/no

### 已知已知
- <事实> [来源] [置信度 L]

### ??? 已知未知
- ??? <缺失数据> — 如果答案是X，结论翻转为Y

### 不确定关系
- <A> -- <B>：可能有关联，但未确认

### 层级追溯
被问层: <X>
上一层: <Y> — [covered/blind]
  - 约束1: [covered/blind]
  - 约束2: [covered/blind]

### 信号源预判
| 数据源 | 可获得性 | 备注 |
|--------|---------|------|
| <源1> | high/medium/low | |
```

## 失败模式

| 模式 | 预防 |
|------|------|
| 资产搜索不完整——漏了已有的历史报告 | Step 1 四个数据源逐一确认，每个必须 yes/no |
| ??? 节点为零——误以为"全都知道" | 硬约束 ≥ 3。反问："如果我都知道，为什么还要分析？" |
| 层级追溯跳步——从组件直接跳到市场 | Step 3 必须逐级：组件→整机→认证→市场。不跳 |
| 脑补数据源可获得性 | 标注 `low` 时必须说明为什么低 |
