# 多模型路线图

> CORE.md 引用的多模型独立权重路线图（2026-08-14 补档，修复断链）。

## 现状（诚实声明）

三角色全部运行在单一模型上，通过独立 system prompt 实现角色分化——**弱隔离**（共享底层权重）。
"共识"可能是同源噪声，只有独立权重的审计者才能提供真正的独立验证。

## 目标

至少一个角色运行在独立权重模型上，提供真正的独立审计。

## 优先级

1. **审计者**最需要独立性——它是质检层，与编写者同源即失去意义
2. 其次整合者（综合判断）
3. 探索者最后（反例搜索受益于多样性，弱隔离可接受）

## 阶段

| 阶段 | 内容 | 状态 |
|------|------|------|
| P0 | 单模型多 prompt（当前） | ✅ 运行中 |
| P1 | 审计者接入独立模型 API（如 DeepSeek 独立调用） | 待落地 |
| P2 | 三角色多模型 + 跨模型共识验证 | 路线 |

## 约束

- 独立模型调用的判断须走 decision-log（记录 model 字段，供校准对比）
- 多模型成本更高，P1 只迁移审计者（最高 ROI）
- 不强依赖"多模型才正确"——单模型多 prompt 已被 Stock 63 只全量分析验证够用，多模型是增强非必需
