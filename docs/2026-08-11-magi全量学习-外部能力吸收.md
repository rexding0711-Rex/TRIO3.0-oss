# Magi 全量学习——外部能力吸收报告

> 日期: 2026-08-11 | 分析: TRIO 三视角（Kimi 发散 / DeepSeek 审计 / Claude 工程）| 对象: EDLee01/magi v0.1.13 (MIT)
> 方法: 全量克隆 + 三模块代码级分析（记忆/路由/工具/Skill/Plan）+ 架构文档

---

## 一、Magi 是什么

**可组合的 AI Agent 运行时**（开源、终端运行）。核心主张：开发者不是"用一个 agent"，而是"重组一个 agent"——把 Model/Tools/Skills/Harness/Memory 五层拆开，可替换可组合。

**与 TRIO 的关系**：Magi 是"工程视角：怎么搭 agent 骨架"，TRIO 是"认知视角：怎么让判断可靠"。不冲突，互补。

---

## 二、架构全景

```
TUI/CLI/Control API
  → Agent Runtime
    ├─ Model Router（alias → provider:model，fallback）
    ├─ Agent Loop（重试→切换→并行工具）
    ├─ Plan Mode（状态机 + 执行守卫）
    ├─ Session Manager（SQLite）
    ├─ Memory（文件树 + SQLite 图 + LearningDraft）
    ├─ ToolSearch（按需加载工具 schema）
    ├─ Skill Loader（独立分发）
    ├─ Harness（分散机制合称）
    ├─ Hooks（27 生命周期事件）
    └─ Peer Dispatcher（LAN 多机）
```

## 三、五大机制详解（代码级）

### 1. 记忆系统：文件树 + SQLite 图 + LearningDraft 三件套
- **存储**：`memory/` 类型化文件树 + SQLite 图（memory_nodes 带 weight/use_count + edges：supersedes/conflicts_with 等）
- **LearningDraft**：任务结束后，复杂度阈值（≥4 工具/≥2 失败）或显式关键词触发 → 生成 JSON 草稿（status=pending）→ **人工 apply/reject 前不入库**
- **回灌**：recall 规划器（关键词启发式或 LLM planner）按预算分配 → 图检索（词法+边传播+supersedes 升降权）→ 注入 `[Relevant Memory]`
- **自校准**：命中即 markUsed 强化权重（使用即证据）；用户反馈 useful/irrelevant/wrong 改权重；**supersedes 让被纠正的旧记忆在检索时主动降权出上下文**；45 天未用衰减、重复节点合并

### 2. 模型路由：硬编码规则打分（非模型判断）
- alias（fast/main/deep）→ classifyTask 关键词正则分类 10 种任务（quick/coding/reasoning/planning/long_context 等）→ scoreCandidate 按 family×role×上下文打分 → 最高分 alias
- provider fallback：先指数退避重试同一端点（isFastFailNetworkError 死端点快速失败），再切 fallback 候选

### 3. ToolSearch：按需加载（省上下文，不省启动）
- minimal profile 初始仅 6 工具，ToolSearch 工具按 `Pack:/Tool:` 结果在下轮注入完整 schema
- **但 MCP 服务器仍全量贪心启动**（discover 遍历所有 server）——不解决 TRIO 的 MCP 慢启动

### 4. Skill：强分发 + 弱结构
- SKILL.md 纯 Markdown 无强制字段（结构弱）
- **独立分发强**：GitHub API 安装（不 clone）+ blob sha 内容寻址 + core/deferred 两级物化 + manifest.yaml 声明加载契约

### 5. Plan Mode：完整状态机
- submitted → approved/needs_revision + 修订链 + 跨会话 adopt + 多计划合并/冲突检测
- **read-before-write 执行守卫**：已批准计划后，写文件前必须先读（强约束）
- 注意：批准后不自动退出 plan 权限模式（需手动切）

### 6. Harness：无独立单元（重要发现）
README 声称"Harness 定义 agent 行为"，但代码里**没有 harness 模块**——是 system-prompt + AGENTS.md + hooks + 权限模式的分散组合。**TRIO 的面具/角色是真实文件单元，反而更实在**。

## 四、与 TRIO 的五大对标

| 机制 | Magi | TRIO | 判定 |
|------|------|------|------|
| 记忆回灌 | 使用即强化 + 反馈权重 + supersedes 抑制 + 衰减遗忘 | 决策校准飞轮（预测注册→验证） | ⭐ magi 强在"相关性自校准"，TRIO 强在"决策级置信度账本"，**可拼合成完整飞轮** |
| 模型路由 | 硬编码规则打分 + fallback | 单模型多 prompt（弱隔离短板） | ⭐ magi 提供现成的"角色→模型"映射模板 |
| 工具加载 | ToolSearch 按需 | MCP 按需（8-11 诊断慢启动） | ToolSearch 不解决 MCP 慢启动，需另设计 |
| Skill | 强分发弱结构 | 结构化流程弱分发 | 互补：magi 分发机制值得抄 |
| Plan | 状态机 + 执行守卫 | 面具 Plan 模式（单会话流程） | magi 计划可持久化/合并/审计，值得借鉴 |

## 六、反证与风险（DeepSeek 审计）

- **Magi 是 beta 质量**（v0.1.13），接口可能变——借鉴机制，不依赖其实现
- **硬编码路由**：classifyTask 靠关键词命中，复杂任务选模型质量有限（TRIO 若抄，需加"任务描述语义"维度）
- **ToolSearch 省 token 不省启动**：TRIO 8-11 的 MCP 慢启动问题仍需独立解决
- **Harness 概念与实现不符**：README 声称 vs 代码实际有落差——**提醒我们审阅外部项目要验代码，不轻信文档**

---

## 七、核心洞察

> **Magi 最值得 TRIO 抄的不是"工具"，是"回灌闭环"**——让每次使用的记忆自动强化、每次纠正的记忆自动降权、每条经验经人工审阅才入库。TRIO 已有预测注册账本，缺的是"经验复用层"。两者拼起来 = 完整的学习飞轮。
