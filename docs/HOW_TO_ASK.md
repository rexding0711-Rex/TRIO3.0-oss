# TRIO 3.0 提问指南

> 一份用问题写成的使用手册。
> 不教你"怎么用 TRIO"——而是帮你发现**你真正想问的是什么**。

---

## 〇、先问自己三个问题

在敲下任何命令之前，停 30 秒：

**1. 我要的是一个答案，还是一个判断？**

TRIO 不擅长"XX 公司成立于哪一年"（搜索引擎擅长）。
TRIO 擅长"这家公司的增长质量比同行好吗？证据在哪？怎么被证伪？"

**2. 如果 TRIO 告诉我"你的直觉是错的"，我愿意看下去吗？**

如果你的真实需求是"帮我找证据支持我已做的决定"——TRIO 不适合。
TRIO 的三根柱子之一叫**结构化怀疑**，它的默认立场是"你的假设可能不对"。

**3. 我给了足够的方向，还是只给了一个话题？**

"帮我看看新能源" → 话题。
"对比宁德时代和比亚迪的供应链韧性，我想判断谁的抗风险能力更强" → 方向。

## 一、TRIO 不是更聪明的搜索引擎

| 你会怎么用 | 搜索引擎 | TRIO 3.0 |
|-----------|---------|----------|
| 输入 | 关键词 | 问题 + 约束 + 目的 |
| 输出 | 链接列表 | 结构化分析 + 矛盾标注 + 可证伪条件 |
| 对不确定的态度 | 不显示 | **主动暴露**——哪不确定、为什么不确定 |
| 最擅长 | "是什么" | "为什么""值不值得""风险在哪" |
| 最不擅长 | 判断和综合 | 事实检索（它会把事实检索外包给搜索，但核心价值是**判断**） |

> 如果你只是想知道"XX 公司去年营收多少"——百度/Google/Perplexity 更快。
> 如果你想问"XX 公司的营收质量如何？现金流和利润对得上吗？什么信号值得警惕？"——TRIO 是你的工具。

## 二、你的问题长什么样？（自诊三步）

### 第一步：它属于哪种分析？

| 你的直觉 | 可能是这类分析 | 触发方式 |
|---------|-------------|----------|
| "我想搞清楚这家公司到底行不行" | 公司尽调 | `/all 尽调 <公司名>` |
| "我想知道 A 和 B 谁更强" | 竞品对比 | `/all 竞品对比 <A vs B>` |
| "我对一个人/团队很好奇" | 人物评估 | `/all 人物评估 <人名>` |
| "这个判断靠谱吗？帮我验证一下" | 验证判断 | `/all 验证 <判断>` |
| "我要写一份行业分析/报告" | 内容交付 | `/all 行业分析 <主题>` |
| "我想搞清楚某个行业的格局" | 行业全量/赛道洞察 | `/all 行业全量 <赛道>` |
| "我不知道该用什么命令" | 自由探索 | `/all <任意描述>` |

### 第二步：你的约束是什么？

同样的"我想了解这家公司"，不同的约束产出完全不同：

- "我想了解宁德时代" → TRIO 不知道该重点看什么
- "我想了解宁德时代，**重点关注海外产能风险**" → TRIO 知道往哪发力
- "我想了解宁德时代，**重点关注海外产能风险，我在评估是否减持**" → TRIO 火力全开

约束 = 你给的方向。方向越具体，分析越深。

### 第三步：你允许 TRIO 质疑你吗？

如果你带着一个已经做好的判断来找 TRIO，TRIO 会质疑它——这是设计好的，不是 bug。

- "帮我证明宁德时代的供应链没问题" → 不适合。TRIO 会反问你"为什么你觉得没问题"
- "帮我评估宁德时代的供应链风险" → 适合。TRIO 会主动找反证

## 三、好问题的三个层次

| 层次 | 特征 | 例子 | TRIO 的表现 |
|------|------|------|-----------|
| 1 · 方向不清 | 只有话题，没有方向 | "帮我看看新能源" | 抓瞎——搜一堆泛泛的资料，分析浅 |
| 2 · 方向明确 | 有目标但缺约束 | "分析宁德时代" | 能用但浪费——覆盖全面但不深入你最关心的 |
| 3 · 方向+约束+目的 | 完整的分析请求 | "分析宁德时代的海外产能风险，重点关注匈牙利工厂进展和欧洲反补贴政策。我在考虑是否减持" | 火力全开——搜索精准、分析深入、结论可行动 |

**升级技巧**：每次提问前加一句"**我真正想知道的是______**"，把横线部分填入，就是你该问的问题。

## 四、提问前自问 5 题（核心框架）

把这张清单放在你面前。每次向 TRIO 提问前，逐条过一遍：

```
[ ] 1. 我要的不是信息，是判断？
         → 是 = TRIO 适合。不是 = 用搜索引擎。

[ ] 2. 我知道自己不知道什么吗？
         → 列出来。哪怕只写一个"我不确定XX"——这比空泛提问好10倍。

[ ] 3. 如果 TRIO 的结论推翻我的预设，我能接受吗？
         → 能 = 可以开始。不能 = 先别用 TRIO，先想清楚你要什么。

[ ] 4. 我给的方向够具体吗？有没有加约束？
         → 加上"重点关注XX"——一句话就能把分析深度翻倍。

[ ] 5. 我要的不是完美的分析，是可以行动的依据？
         → 是 = 可以开始。不是 = TRIO 做不到，它不制造确定性。
```

**如果 5 题都答不上来**，先跟 TRIO 聊一轮：

```
/all 我想了解XX，但不确定从哪开始。帮我理清思路。
```

TRIO 的 router 模式就是为这种情况设计的——它会帮你把模糊变清晰。

## 五、坏问题 → 好问题（对照表）

### 例 1：公司分析

| | 提问 | 问题在哪 |
|------|------|------|
| ❌ | "帮我看看特斯拉" | 只有话题。TRIO 不知道你想看什么——财务？产品？人？供应链？ |
| ✅ | "尽调特斯拉，重点关注：① Cybertruck 产能爬坡真实进展 ② FSD 在中国监管审批的可能性 ③ 马斯克个人风险对股价的影响。我在考虑建仓。" | 三个约束 + 一个目的。TRIO 知道往哪发力。 |

### 例 2：竞品对比

| | 提问 | 问题在哪 |
|------|------|------|
| ❌ | "蔚来和理想谁更强" | 太宽泛。"强"指什么？产品力？财务健康？品牌？ |
| ✅ | "对比蔚来和理想：① 单车经济模型（毛利率/单车SG&A/单车净利）② 现金跑道（现有现金/季度烧钱速度）③ 2026下半年新车 pipeline。我在选投资标的。" | 同一口径下的三个维度。可比、可量化、有目的。 |

### 例 3：人物评估

| | 提问 | 问题在哪 |
|------|------|------|
| ❌ | "评估张一鸣" | 没有方向。是评估他的管理风格？战略眼光？争议历史？ |
| ✅ | "评估张一鸣的决策模式——找 3 个以上关键决策事件（如出售 Musical.ly/推出 TikTok/卸任 CEO），还原他在压力下如何做选择。我要判断如果他仍在字节跳动，面对美国禁令会怎么决策。" | 有方法论、有具体案例、有实际目的。 |

### 例 4：行业分析

| | 提问 | 问题在哪 |
|------|------|------|
| ❌ | "AI 行业怎么样" | 无限宽。AI 从芯片到应用几十个子领域。 |
| ✅ | "AI 视频生成赛道：① 当前格局（Runway/Pika/Sora/可灵/即梦份额）② 单元经济（推理成本/客单价/付费率）③ C端付费意愿是否真实（非PR数据）④ 2026下半年可能的变化。我在看这个方向的投资机会。" | 赛道明确 + 四个维度 + 需求端验证要求 + 目的清晰。 |

### 例 5：决策辅助

| | 提问 | 问题在哪 |
|------|------|------|
| ❌ | "我该不该投这个项目" | TRIO 不会替你做决定，也不应该。 |
| ✅ | "帮我列出投资 XX 公司的三个最强理由和三个最大风险。每个理由和风险附上可验证的证据来源。论证如果哪个假设被推翻，结论会翻转。我自己做最终决策。" | 把"该不该"转化为"证据+风险+翻转条件"。TRIO 帮你梳理，决策权留给你。 |

### 例 6：内容创作

| | 提问 | 问题在哪 |
|------|------|------|
| ❌ | "帮我写一份 AI 行业报告" | 什么角度？给谁看？多深？什么格式？ |
| ✅ | "/内容 AI 视频生成行业白皮书——目标读者是二级市场基金经理，重点放在成本结构和竞争壁垒，需要财务数据支持。输出 Markdown + PDF。" | 读者、角度、深度、格式——四个约束全有。 |

## 六、三个角色：Suggestor、Doer 和 Auditor

TRIO-Pro 用三个角色分工协作——**各司其职，互相校验**：

| 角色 | 它会怎么想 | 什么时候让它上 |
|------|-----------|-------------|
| **Suggestor** 建议者 | "你有没有想过这个角度？" | 你需要**拓宽视野**——找盲区、挖掘隐藏叙事、提出替代方案 |
| **Doer** 执行者 | "给我约束，我来交付。" | 你需要**产出结果**——写报告、拉数据、排计划、出方案 |
| **Auditor** 审计者 | "你说的这些，证据在哪？" | 你需要**被质疑**——风险扫描、矛盾检测、验证结论是否站得住 |

**默认不需要你选择**——TRIO-Pro 会自动判断。
但如果你明确知道自己的需求类型，可以在提问中暗示：

- "我想看看有没有遗漏的角度" → Suggestor 侧
- "我要一个能直接用的交付物" → Doer 侧
- "帮我检查这个结论有没有漏洞" → Auditor 侧

## 七、一句话速查

```
┌─────────────────────────────────────────────┐
│                                             │
│   不 要 问："帮我看看 XX"                    │
│                                             │
│   应 该 问："分析 XX，关注 A/B/C，因为我要 D" │
│                                             │
│   A/B/C = 你关注的维度（别超过 4 个）          │
│   D     = 你的目的（做决策/写报告/理解行业）     │
│                                             │
│   不 要 让 TRIO 替你决定看什么——               │
│   你 比 TRIO 更 懂 你 的 需 求。               │
│                                             │
└─────────────────────────────────────────────┘
```
